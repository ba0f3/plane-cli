# v0.3 Admin / Operations

v0.3 adds instance administration, inventory, audit, health checks, and guarded bulk operations.

## Token diagnostics

```bash
plane-cli admin token
```

Reports:

- principal type and scope level
- bound workspace for WSAT
- visible workspace count
- service-token scopes
- missing recommended admin read scopes
- whether `projects:write` is present for bulk project deletion
- auth-context and workspace-discovery readiness checks

Recommended service-token read scopes for v0.3 admin commands:

- `workspaces:read`
- `projects:read`
- `workspaces.members:read`

## Instance-wide member inventory

```bash
plane-cli admin members
plane-cli admin members engineering
plane-cli admin members --search alice@example.com
```

Without a workspace argument the command scans every workspace visible to the current token and deduplicates users across workspaces. Output includes each user's memberships and role values per workspace.

Per-workspace failures are returned in the structured `errors` array instead of discarding successful workspace results.

## Health

```bash
plane-cli admin health
plane-cli admin health engineering
```

Health checks workspace member and project endpoints, then probes explicit project membership. A workspace becomes `degraded` when any required endpoint fails. The command keeps partial results so it can be used by monitoring and cron jobs.

This is API/readiness health, not infrastructure health. It does not claim to validate PostgreSQL, Redis, workers, object storage, or other Plane runtime components.

## Membership / ACL consistency audit

```bash
plane-cli admin audit
plane-cli admin audit engineering
```

The audit only reports facts visible through the Plane APIs. It does not infer permissions that the API does not expose.

Current findings include:

- workspace member endpoint inaccessible
- project member endpoint inaccessible
- workspace member missing both ID and email
- project member missing both ID and email
- project member not present in the visible workspace member list
- workspace with no visible members
- project with no explicit members visible to the token (`info`, not an error)

Severity levels are `error`, `warning`, and `info`.

## Safe bulk project deletion

```bash
# Dry-run only
plane-cli admin bulk project-delete engineering OLD1 OLD2

# Execute the exact resolved plan
plane-cli admin bulk project-delete engineering OLD1 OLD2 --apply
```

Safety rules:

1. Workspace is always an explicit positional argument. The command never takes it implicitly from config or environment.
2. Dry-run is the default. No DELETE request is sent without `--apply`.
3. Selectors match project UUID, identifier, or exact name.
4. If any selector is unresolved, `--apply` refuses to execute the entire plan.
5. IAT does not fan out destructive operations across workspaces.
6. Apply mode reports each project result and returns a non-zero exit status if any deletion fails.

Service tokens need `projects:write` for apply mode.

## Structured output

All v0.3 commands support the normal global output option:

```bash
plane-cli admin audit --output json
plane-cli admin health --output yaml
```

The outputs are intended to be consumed directly by cron jobs, monitoring, goclaw, and other automation.
